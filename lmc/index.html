Three digits and the negative flag

This simulator uses the classroom convention of three unsigned decimal digits: ACC and mailboxes store 000–999. ADD discards the thousands carry, so 999 + 2 → 001. SUB displays its result modulo 1000: 3 − 5 → 998, with a separate N = 1 flag so BRP can detect a negative result. The value 998 alone does not indicate the sign.

The displayed ACC value for a negative result is an explicit simulator convention; the lectures do not fully specify that display. LDA and INP clear N; ADD / SUB update Z and N; STO, OUT and branches preserve the flags. STO stores only the three-digit value, not N. Loading it again with LDA treats it as non-negative data.

Syntax and stepping

Supports labels (e.g. LOOP SUB ONE), explicit addresses (e.g. 99 DAT 0）、//、; or # comments, and the STA / STORE / LOAD aliases. Machine code accepts one word per line or the explicit address format 00 901 . XX is a mailbox address, not an immediate value.

“Step instruction” finishes the current instruction; “Step RTL” performs one micro-operation. PC points to the next instruction, but during fetch it still points to the address being fetched. Its two-digit counter wraps from 99 to 00. HLT stops without incrementing PC. Unallocated mailboxes initially contain 000, which executes as HLT.

Cycle counts follow the Lecture 5.2 table: LDA / STO / ADD / SUB = 7, INP / OUT = 5, branches = 4, and HLT = 3. The lectures split some RTL examples differently; this simulator consistently uses the table, with one cycle per RTL step. Time at 100 MHz = cycles ÷ 100, in μs.

Automatic execution pauses when INP has no input. Add data, then click Run. Execution pauses after 10,000 consecutive instructions to let you inspect a possible infinite loop; you may resume. Output belongs to the current run and is cleared by assembling or resetting.
